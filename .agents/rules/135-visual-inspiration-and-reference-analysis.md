# Visual Inspiration and Reference Analysis

**Severity: HIGH**  
**Activation:** Model Decision whenever the task includes a new visual design, redesign, landing page, dashboard, marketing page, brand-led experience, interaction design, or supplied visual references.

## Purpose

Use external design galleries and real products as research inputs, not as templates to copy. The goal is a deliberate interface with product-specific visual language, not an obvious AI-generated composition.

## Inspiration sources

Useful sources include, where relevant:

- Awwwards — award-level web craft, interaction, composition, and experimentation.
- Brandfetch — brand identity systems, logo/color context, brand presentation, and brand asset consistency.
- Godly / Recent — restrained contemporary web direction and editorial/product presentation.
- SiteInspire — layout, typography, content hierarchy, and visual systems across real websites.
- CSS Design Awards — frontend craft and interactive execution.
- Mobbin / Page Flows — real product UI and interaction patterns rather than speculative concepts.
- Behance / Dribbble — broader art direction, visual exploration, and component ideas; treat shots as concepts, not product truth.
- Land-book / Lapa Ninja / One Page Love — landing-page structure, conversion patterns, and content hierarchy.
- The FWA — experimental interaction and motion references when the product genuinely benefits from them.

The exact source is secondary to the design problem. Choose sources that answer the question being solved.

## Required process

Before inventing a visual direction:

1. Inspect the product, repository, existing design system, brand assets, content, target users, and supplied references.
2. Define the design problem: hierarchy, trust, conversion, readability, differentiation, navigation, data density, storytelling, or interaction.
3. Study multiple references rather than copying one site. Prefer at least 3 references for a material redesign and identify what each contributes.
4. Extract principles, not pixels: typography behavior, density, grid logic, spacing rhythm, image treatment, color relationships, interaction patterns, motion language, and content hierarchy.
5. Record the reference-to-decision mapping before implementation when the visual change is substantial.
6. Adapt the ideas to the product's content, accessibility needs, responsive constraints, performance budget, and existing brand.
7. Verify the result at real viewport sizes and against the product requirements.

## What may be borrowed conceptually

- information hierarchy
- editorial/grid composition
- typography pairing or scale relationships
- spacing rhythm
- interaction patterns
- navigation structures
- motion principles
- visual density
- image/art direction treatment
- ways of presenting brand data or content

## What must not be copied blindly

- logos or proprietary brand assets
- distinctive illustrations or photography without permission
- exact page copy
- source code
- exact layouts whose identity depends on a specific brand
- unique interactions that are unrelated to the product
- trademarked or brand-specific visual identifiers

Do not reproduce a reference site one-for-one. A reference is evidence for a design decision, not an instruction to clone the site.

## Human-made design test

Reject or redesign work that looks like a generic generated template, including unexplained combinations of:

- gradient-heavy hero sections
- giant text with no content reason
- excessive rounded cards
- glassmorphism used as decoration
- repeated floating blobs or abstract 3D shapes
- arbitrary neon accents
- excessive section separators
- dashboard bento grids used without information architecture need
- fake statistics or invented testimonials
- generic startup/AI copy
- animation added only to appear sophisticated

These patterns are allowed when the researched references and actual product justify them. Every non-trivial visual flourish should have a reason.

## Report

For substantial visual work, record:

| Reference/source | Observed principle | Product-specific adaptation | Verification |
| --- | --- | --- | --- |
| Source URL/name | What was actually useful | What changed for this product | How it was checked |

State clearly when a decision came from an existing product requirement, repository convention, supplied brand reference, or external inspiration.
