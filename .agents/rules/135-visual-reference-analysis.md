# 135 — Visual Reference Analysis

**Severity:** HIGH when screenshots, designs, recordings, or existing reference pages are supplied

Treat visual references as evidence about observable product behavior and visual intent.

Inspect hierarchy, typography, spacing, alignment, density, interaction affordances, states, imagery, responsive behavior, and content—not just colors and shapes.

Separate:

- `Observed`: directly visible behavior or structure
- `Inferred`: likely implementation intent supported by context
- `Assumed`: a choice made because evidence is absent
- `Missing`: information required to reproduce behavior accurately

Do not copy inaccessible, broken, or obviously accidental behavior merely because it appears in a reference. Preserve product intent while applying the repository's technical and accessibility constraints.

If the reference conflicts with an existing design system, identify the conflict rather than silently creating a third visual language.
