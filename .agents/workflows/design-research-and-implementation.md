# Design Research and Implementation

Use for new pages, redesigns, landing pages, dashboards, brand-led surfaces, or substantial visual changes.

1. Inspect the existing app, design tokens, components, brand assets, content, framework/version, responsive behavior, and accessibility conventions.
2. Define the actual UX/design problem.
3. Research multiple relevant references. Use award galleries for craft, product libraries for proven interaction patterns, and brand-data sources for identity context.
4. Record observed principles separately from assumptions.
5. Form a product-specific visual thesis before coding.
6. Implement with existing primitives and tokens where possible. Introduce new primitives only when the product requires them.
7. Add all meaningful states: loading, empty, error, disabled, success, hover/focus/pressed, responsive variants, and reduced-motion behavior when relevant.
8. Validate real content and realistic data. Do not use invented content merely to make screenshots attractive.
9. Run the project and inspect the real UI at representative viewport sizes.
10. Check keyboard navigation, focus visibility, contrast, semantics, touch targets, text wrapping, overflow, and reduced motion.
11. Compare implementation against the design thesis and requirements, not pixel-for-pixel against an inspiration site.
12. Remove decorative elements that do not improve hierarchy, comprehension, brand expression, or interaction.
13. Report references, design decisions, verification evidence, and remaining gaps.
